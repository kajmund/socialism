# GLiNER2 / GLiNER2.5 — Engineering Evaluation

Research date: 2026-10-29. All facts below were verified against primary sources (GitHub repo, GitHub API, Hugging Face API/model cards, PyPI, arXiv, Fastino blog) unless marked "secondhand".

## 1. What GLiNER2 is

[GLiNER2](https://github.com/fastino-ai/GLiNER2) is a schema-conditioned encoder family for information extraction: **zero-shot NER, text classification, structured/JSON record extraction, relation extraction, and span attributes**, in one forward pass ([README](https://github.com/fastino-ai/GLiNER2#readme)). Labels are supplied as a schema at inference time — no per-task fine-tuning required; fine-tuning (full or LoRA) is also supported.

Two architectures share one API:
- **`span` (GLiNER2 / `SpanExtractor`)** — a fixed-width span grid. Max span width ~12 words; longer expressions are structurally invisible ([Fastino blog](https://fastino.ai/blog/gliner2-5-span-free-information-extraction)).
- **`boundary` (GLiNER2.5 / `BoundaryExtractor`)** — sparse start/end boundary prediction with a rerank head; any span length that fits the 4,096-word encoded window, linear scaling in document length, plus joint entity–relation decoding (`JointIE`) and constrained classification ([blog](https://fastino.ai/blog/gliner2-5-span-free-information-extraction), [multi-v1 card](https://huggingface.co/fastino/gliner2.5-multi-v1)).

vs. GLiNER 1.x ([original repo](https://github.com/urchade/GLiNER)): 1.x was zero-shot NER-only; GLiNER2 adds multi-task schema composition ([paper](https://arxiv.org/abs/2507.18546)); GLiNER2.5 replaces span enumeration with boundary prediction.

## 3. Training methods and data

GLiNER2 (span): 254,334 examples — 135,698 real-world (news 74k, law 19.8k, Wikipedia 17.9k, PubMed 16.4k, ArXiv 7.1k) annotated by GPT-4o, + 118,636 GPT-4o synthetic ([paper §3.1](https://arxiv.org/abs/2507.18546)). GLiNER2.5: synthetic data generated by the Fastino Data Agent across a domain×task matrix ([blog](https://fastino.ai/blog/gliner2-5-span-free-information-extraction)). Local fine-tuning: JSONL format, `ExtractorTrainer`, LoRA adapters (~2–10 MB), multi-GPU ([README](https://github.com/fastino-ai/GLiNER2#readme)); hosted training via [Fastino API](https://agent.fastino.ai).

## 4. CPU/GPU, latency, quantization

CPU-first and explicitly supported ("fast local inference on standard hardware — no GPU required", [README](https://github.com/fastino-ai/GLiNER2#readme)); CUDA and MPS also supported. **No official latency table.** Community-reported CPU numbers (secondhand): ~3,950-char document on span base ≈ 0.30–0.34 s full-length vs ~0.125 s with `max_len=384` ([PR #79](https://github.com/fastino-ai/GLiNER2/pull/79)); decoder GRU ≈ 6–21 ms CPU ([PR #144](https://github.com/fastino-ai/GLiNER2/pull/144)). Long documents: native chunked APIs (`extract_*_long`, chunk_size=384 default); spans/relations are kept only if endpoints fall in the same chunk ([multi-v1 card](https://huggingface.co/fastino/gliner2.5-multi-v1)).

VRAM: weights ~594 MB FP16 (287M multi, card-verified); ~0.4 GB (194M) and ~0.15 GB (74M) FP16 are derived estimates. Options: `quantize=True` (fp16), `torch.compile`, FlashDeBERTa/DisentangledFlash GPU kernels. **No official ONNX/int8**; the ONNX request ([issue #51](https://github.com/fastino-ai/GLiNER2/issues/51)) is open; community exports exist ([gliner2-onnx](https://github.com/lmoe/gliner2-onnx), [hugot-gliner2](https://github.com/josejuanmontiel/hugot-gliner2), vLLM route).

## 5. Maintenance and known issues

2,426 stars, 217 forks, 71 open issues; created 2025-07-07, last push 2026-10-20 ([GitHub API](https://api.github.com/repos/fastino-ai/GLiNER2)). Latest release **v2.1.0** (2026-10-09, [PyPI](https://pypi.org/project/gliner2/)); v2.0.0 (2026-08-24) shipped GLiNER2.5; active core team (urchade) + contributors. Relevant to long legal expressions / Swedish compounds: the span-architecture ~12-word width cap (solved by 2.5 boundary); whitespace word splitter keeps hyphen/underscore runs as one token ([PR #181](https://github.com/fastino-ai/GLiNER2/pull/181)); v2.1.0 fixed analogous Indic combining-mark splitting ([release](https://github.com/fastino-ai/GLiNER2/releases/tag/v2.1.0)). Swedish compounds are single whitespace-delimited tokens, so the splitter keeps them whole. Open: relation-extraction inconsistencies ([#101](https://github.com/fastino-ai/GLiNER2/issues/101)); `extract_entities_long` bug + duplicate span issue ([PR #137](https://github.com/fastino-ai/GLiNER2/pull/137)).

## 7. GLiNER2.5 and naming

GLiNER2.5 is not a separate repo: it is the boundary architecture inside the `gliner2` library (≥ 2.0.0, [release](https://github.com/fastino-ai/GLiNER2/releases/tag/v2.0.0)), checkpoints `gliner2.5-*`. Naming caveat: `GLiNER2.5-Decide` is a **span** checkpoint despite the name; `GLiNER2.5-multi-Decide` is boundary ([README](https://github.com/fastino-ai/GLiNER2#readme)). Benchmarks: 2.5 Multi overall F1 56.17 vs 2 Multi 56.09 (extraction slightly lower: 46.40 vs 47.56; XNLI +24.75) ([blog](https://fastino.ai/blog/gliner2-5-span-free-information-extraction)).
